# Music Analysis

此為使用者專案的自訂技能，非 Spotify、librosa 或其他工具作者發布的官方技能。沿用可信原始專案與 GuitarScribe 的分析程式；技能本身不附辨識模型，也不會自動下載依賴。

## 確定要辨識的對象

從使用者要求與現有資料判斷目標：人聲主旋律、器樂主旋律、單一樂器的多音轉錄、拍格、和弦，或既有候選的診斷。只有目標或來源確實缺失且會影響結果時才詢問。不要把「旋律」默認成所有發聲音符，也不要把人聲停止當成整曲沒有旋律。

GuitarScribe 工作先讀 [專案入口](references/guitarscribe.md) 中與任務相關的檔案；外部工具選擇與判讀讀 [工具及評估](references/methods.md)。依目前程式及適用的專案規則執行；參考文件是定位入口，不是永久固定的專案現況。

## 分析流程

1. **固定輸入與基準。** 記錄來源檔與 SHA256、錄音版本、分析片段 `[start, end)`、來源時間基準，以及現有 score／人工修訂版本。先查看既有分軌與分析快取，避免重跑已完成的昂貴推論。快取須匹配來源、片段、引擎版本及參數。
2. **檢查可用環境。** 讀現有依賴、設定與 CLI；使用現有虛擬環境或容器。確認選定引擎、權重、分軌工具及硬體是否可用。安裝 skill 不代表所有引擎已安裝；缺少依賴要明確報告。需要新增時採原始專案、隔離環境及可追蹤版本，不在分析腳本中偷偷自動 pip install。
3. **定位問題層。** 分開檢查來源選擇／分軌、原始 F0、音符起訖與分音、拍格／小節、後處理、移調／指法及播放排程。從症狀涉及的層開始，避免為修顯示或播放問題重調辨識模型。
4. **執行適合的工具。** 乾淨單旋律可用 pYIN；多音轉錄可用 Basic Pitch；完整混音需先判斷旋律所在聲部，分軌只是輔助。沿用現有引擎選擇；新引擎先當隔離候選，不因技能的工具列表自動換預設。
5. **保留原始證據。** 分開保存原始輪廓／候選音符與後處理結果。保留未發聲區段、時間戳、實際 sample rate／hop、裁切偏移、引擎與模型版本、參數、耗時及 fallback 警告。數值 confidence 只能依其實際定義解讀，不是經校準的正確機率。
6. **依證據評估。** 有可靠且時間對齊的參考才計算正確率；先確認標註覆蓋、來源雜湊與評分器限制。沒有參考時仍可完成擷取與異常診斷，但音樂正確性標為未知。另一模型、網路譜或模型間一致度只作比較來源。
7. **交付可重現結果。** 報告分析範圍、實際引擎、產物位置、分層指標／異常、缺失證據及可執行的下一步。除非有直接聆聽證據，不宣稱「聽起來正確」。若需要主觀確認，提供具體時間與問題，繼續其他已授權且可客觀驗證的工作。

## 時間與音樂語義

- 區分原音訊時間、片段局部時間、拍點及小節時間。記錄映射且只套用一次裁切偏移；重採樣後以實際 sample rate 計算 `hop_seconds`，注意 frame centering 與 padding。
- 不用量化、平滑、補音或強制調內音掩蓋偵測失敗。若任務需要修譜，另存修訂並列出對原始結果的改動。
- 區分有聲／無聲、缺標註與來源分離失敗。空結果不能自動解釋成真正休止；未標註也不等於無旋律。
- 主旋律可能在人聲、吉他、鋼琴等聲部間轉移；不把最高音、最大音量或 vocals stem 當成普遍主旋律規則。
- 區分實際發聲音高、記譜音高、移調及 capo 和弦形狀。比較音訊與譜時先轉到相同的發聲音高基準；不要為了分數任意移八度。
- MIDI／MusicXML 匯出成功只證明產物可生成，不證明音符或節奏符合原曲。

## 比較與改善辨識器

普通單次分析不必啟動完整研究流程。使用者要求改善引擎時，固定一個主要假設、未修改的 baseline、評分範圍及停止條件，先做小範圍可重現比較，再依工作範圍擴展跨曲驗證。

使用相同參考與時間基準比較 baseline／candidate，分開報音高、八度、漏音／多音、起訖、拍速層級、小節相位與和弦邊界。未用來調參的確認組與已反覆使用的診斷組分開，記錄模型訓練資料可能重疊。不要把單曲片段、合成測試或工程回歸提升成未見完整歌曲的品質結論。

預先約定的比較失敗就保留失敗結果並定位原因；不要事後縮短片段、重對齊、放寬容差或逐曲硬編參數使分數通過。新假設需另立實驗記錄。缺參考時停止做無依據的準確率調參，轉為補足評估條件或完成可驗證的工程工作。

候選輸出使用獨立目錄，保留來源與人工接受的工作譜。分析要求本身不授權上傳音訊到第三方、購買服務或發布候選；有既有明確授權時沿用其範圍。
