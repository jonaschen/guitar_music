# GuitarScribe 自主開發

改善「YouTube 選歌 → 分析 → 看和弦、聽原曲跟彈」的可靠性及手機／桌面操作。交付可驗證的產品進展，不以測試數、報告數或模型試驗數代替改善。使用者無暇測試不是全案停止條件。

## 接續工作

先找 Git 根目錄並確認包含 `guitarscribe/backend`、`guitarscribe/frontend`。路徑以下皆相對該根目錄；安裝位置不是專案目錄。

1. 讀 `guitarscribe/docs/Next_Decision.md` 最新段落、`guitarscribe/docs/Autonomous_Development.md` 工作表、Git 狀態及近期提交。需要長程範圍時才讀 `guitarscribe/Roadmap_status.md`。較新的使用者決策優先；不要把舊段落的「等待試聽」重新當成阻塞。
2. 對照現行程式與產物核實狀態。只讀所選任務相關文件；[專案導航](references/project-map.md) 提供入口。資料缺失標成未知，不重建成已通過。
3. 優先最新使用者問題及阻斷主要流程的回歸，再選能降低多首歌曲失敗／人工修正的共同問題。沒有新產品問題時才做必要維護。不要用大量低價值整理避開品質主線。

## 持續執行的循環

每個工作段落選一個有證據的問題，記錄重現、預期改變、驗證方法與停止／退回條件；直接完成分析、修改及驗證，不停在提案。

- 先重現，再修能解釋失敗的那一層。分開下載、拍點、小節重音、和弦名稱、切換時間、刷奏排程、譜面及播放；不要一次變好多層卻宣稱知道根因。
- 工程問題自行處理：例外與輸入解析、保存／復原／重載、時間一致性、播放事件、響應式溢出、錯誤反饋、來源資訊、相關效能問題。自行跑適當測試與實際流程；可自動驗證的操作不要再交使用者。
- 對音樂品質只能得到間接證據時，完成離線診斷與獨立候選，標記 `awaiting_human`。保留可逆入口及既有預設，轉做下一個 `ready` 任務；不因一項待聽便結束所有開發。
- 每項假說有明確失敗判準。證據推翻時記錄結果，停止同方法重試；沒有新證據，不更換名稱、片段或小幅調參再問同一題。新證據或不同可否證機制才重開。
- 一個實質段落完成後更新工作表、提交所屬檔案，在現有授權下 push，再選下一項工作。不要為了製造提交拆成空洞進度；不要無新修改、失敗或疑點就重跑相同檢查。
- 使用者回來提問時簡答並納入新資訊；除非明確叫停或改目標，保留原工作主線。接手／壓縮上下文後從工作表續做。

## 音樂變更的證據

在看候選結果前，固定共同規則、錄音／時間範圍、比較基準、工程閘門及可接受的變動。包含已接受控制組、已知失敗組及未用來調整規則的保留來源；相同歌曲不同錄音分開標示，重複 job 不計為新歌曲。資料不足就限定結論，先用已有授權素材，不要求使用者為每輪補來源。

- 優先重用相同音訊、快取模型輸出及解碼設定，只有輸入、模型程式或可檢驗假說改變時才重跑昂貴推論。批次結果寫入新的輸出路徑，保留原分析、人工修訂及已接受音檔。
- 比較音訊／譜面／manifest 的版本或雜湊、失敗率、有效覆蓋、密度突變、越界／漏刷、既有控制組退步；依任務選有意義的指標。結構通過不等於拍子或和弦正確，沒有真值不報音樂準確率。
- 不用單曲專屬閾值、全面刪短和弦或放寬保護來增加通過數。不把不確定時間表畫成已知小節。保留休止、弱起及人工修改；需要改變它們時明列證據與影響。
- 刷奏起音來自節奏排程；「換和弦」不等於「刷一下」。小節內新和弦沒被演奏，需另外檢查和聲覆蓋，不能只因有每小節第一拍就說伴奏正確。
- 純時間變更須證明沒有偷改和弦內容；純 UI 變更須證明沒改播放／保存資料。音樂候選升預設依實際需要的人耳證據決定，已接受範圍以來源、版本及時間段為準，不擴張到整曲或其他品質層。

## 精簡人類驗收

只留下人耳判斷的合拍／和聲／自然度，以及主觀 UI 易用性。先完成工程閘門、確認入口可用、保存基準與候選，才加入待測表。工程失敗候選不交人耳。

同類問題合併到一個入口，通常選 2–3 個能改變決策的例子；長度依問題足以辨認，不機械截成過短片段。說明目的、最短操作、回報選項（包括無法判斷），以及各結果會採取什麼下一步。驗收前固定比較條件；有必要才盲聽，不假稱真正盲測。

不重問已接受的同份素材，也不不斷新增相同假說的 A/B。沒有新必要人類決策就明說「目前不需要你測試」，不要把跑測試、收 log 或查 API 轉交使用者。

## 工作紀錄與交付

維護 `guitarscribe/docs/Autonomous_Development.md` 為短工作表，不複製整份歷史。每項保留：ID、問題／證據、狀態（`ready`／`in_progress`／`awaiting_human`／`blocked`／`done`／`rejected`）、下一步、產物／驗證、決策或退回條件。待聽項另外綁來源、片段、版本及問題。完成項簡記到足以避免重做。

報告用繁體中文，交代本段投入、已證實的改善、未知與退步風險、下一項工作；只報實跑過的驗證。沒有改善也是結果，不能改寫成品質通過。

正常修正、測試及既有授權範圍的 commit／push 持續進行，不重複求同意。只提交本次所屬檔案；遇到既有未提交修改或他人並行工作，隔離工作或協調，不覆寫。需要部署時讀 [專案導航](references/project-map.md) 的維運入口，確認當前服務與分析工作狀態再操作。

## 本專案範圍與結束條件

- 主旋律已停止並隱藏；不因自主開發重新啟用。保持獨立產品方向。最新使用者明確改變決策才調整這些限制。
- 不因使用者不在，擴大成購買服務、外部上傳音訊、公開私人素材、擴大網站存取或聯繫他人。沿用已有授權；真的缺必要授權時先完成可審閱結果，該項留下具體阻塞，繼續其他工作。
- 單一 session 可執行全部流程。使用者或適用指示授權並行時，助手適合獨立反例／回歸檢查；主 session 統一整合，避免多人同改核心或同時部署。不要求使用者另外開 session 才能開始。
- 不因成本假設、出現一項待聽或固定小任務數自行停下。當仍有已授權、有證據且可驗證的工作時繼續。
- 使用者叫停、執行環境限制，或所有有價值的獨立工作確實被必要輸入阻塞時，留下可接續檢查點，具體說明剩餘依賴；不以重複巡檢或低價值改動假裝持續改善。
- Skill 是執行中的工作方法，不是排程器。不得聲稱結束回合、關閉代理或主機休眠後仍自動工作；本 skill 不自行建立 cron、背景代理或排程。另有排程授權時才設定，並誠實說明本機可用條件。
