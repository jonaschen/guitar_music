# 本輪集中測試：八小節修譜與譜面

目的：確認分析結果可以被可靠地人工校正、保存及讀譜。使用者已確認舊分析失效，本版流程從重新分析開始。主旋律自動辨識尚未解決，本輪不要求再次比較旋律候選；分析完成後的操作約需 15–20 分鐘，分析等待時間另計。

## 前提

2026-10-05 本機服務以程式碼唯讀掛載模式啟動，保留已測試 backend 映像的分析依賴。完整重建因會重新安裝基礎系統／依賴而主動取消；沒有將未完成的 build 當成部署成功。已驗證實際 health、MusicXML 調音／附點／和弦、旋律時間與 MIDI header，且 demucs／torch／yt_dlp 仍可用。合成 smoke 不建立 jobs 或 revisions。

若之後需要重新啟動，在 guitarscribe 目錄執行：

```bash
docker compose -f docker-compose.yml -f docker-compose.code.yml up -d --no-build
```

此模式掛載 backend/app、scripts、tests 為唯讀，既有 output 與設定沿用主 Compose；Python 程式更新後需 `docker compose restart backend`，依賴改動則仍需完整建置。若不帶 code override 重新建立 backend，會回到舊映像內的程式，不能視為本輪修正已部署。

部署後另以 `GUITARSCRIBE_LIVE_SMOKE=1 GUITARSCRIBE_UI_URL=http://127.0.0.1:5173 npx playwright test e2e/musicxml-render.spec.ts` 驗證目前服務的 1280px／390px 預覽，兩項通過。分析 job 回應仍使用合成 fixture，MusicXML 由實際 8000 API 產生；不宣稱既有歌曲來源音訊已驗證。

- 舊修訂若仍有 ID，先另行記錄；不要把舊修訂直接載入新分析後接著改，以免混用不同裁切起點／音符版本。這次先用新分析建立獨立基準版本。
- 小節分界使用分析後的秒數，不是 MV 原始時間。若分析前略過 19 秒，不要再額外減一次。
- 修訂與來源音訊分開：舊 job 失效不必然表示修訂也消失，但單靠修訂無法恢復來源音訊；這次重新分析是為取得可對照的新來源工作。

## A. 重新分析與時間起點

1. 開啟 `http://localhost:5173`。若網頁已開著，先重新整理；目前服務已啟動，不必先重啟。
2. 選原本同一份歌曲檔。使用本機檔時，清空 YouTube video URL；網址不空白時會優先使用網址。
3. 設定「分析前略過開頭（秒）」：
   - 若仍是你確認前 19 秒非歌曲的同一份《小手拉大手》MV，填 `19`。
   - 若換成已裁掉開場的音檔，填 `0`，不可再刪一次。
   - 這只是裁掉開場，不表示新 0 秒一定就是第一小節第一拍。
4. Melody focus／Vocal isolation 儘量使用前次設定，並記錄本次選項。若不記得，這次先測有人聲的主歌／副歌，可選 `Vocal melody (Beta)`，勾 `Isolate vocals first`；會較慢，也不保證旋律正確。不要為測本輪編輯功能同時切換多種引擎；人聲模式不適合拿來判定器樂間奏是否成功。
5. Chord detail 可選 `Standard`；本輪不測不同和弦複雜度的比較。確認來源是你有權使用的內容，按 `Start analysis` 一次即可。
6. 等待完成。保留畫面上的工作 ID 或含 `?job=…` 的網址。若出現 Failed to fetch、失敗或持續卡在同一階段，先記下階段、進度、已等待多久與錯誤截圖，回報後再處理，不要連續重送分析或重啟。
7. 完成後選上方音軌 `Original`，播放開頭 5–10 秒。預期是裁切後的來源，且頁面提示「播放 0 秒 = 原檔 19 秒」（若填 19）。新时间 31 秒才對應原檔 50 秒；後續請統一回報畫面顯示的分析後秒數。

**通過條件：** 分析完成、來源能播放、時間起點符合設定。若這一段不通過，先停在這裡，不需要勉強做下面的音符測試。

## B. 保存未修改的基準版本

1. 展開 `旋律人工編輯 · Melody editor`。
2. 尚未修改前，按 `Save new revision`，等待成功訊息。
3. 複製「版本 ID」到筆記，標為「A：新分析原始基準」。不要只記在剪貼簿，後續新版本會換 ID。
4. 可另外用 `Download JSON` 備份工作譜；JSON 不包含原音訊。

**通過條件：** 有明確保存成功訊息及非空白版本 ID。若保存失敗，不要重新整理以免丟失工作內容；先備份 JSON 並回報。

## C. 選八小節與來源對照

1. 在 Melody editor 的「起始小節」先選 `Bar 28`，顯示小節數選 `8`。
2. 重新分析可能改變拍點及小節號，Bar 28 不一定仍是舊片段。若該區沒有音符，用「下一個有音符的小節」或起始小節選單，挑一段主歌／副歌；不要選尾端不足八個完整小節的段落。
3. 確認編輯器的「所選 …–…s」時間範圍，記下起始小節與秒數。
4. 上方先選 `Original`，再回編輯器按「對照來源片段」。此按鈕使用上方選定的來源音軌；若上方選的是 Vocal stem，聽到的就不是原始混音。
5. 按「暫停，保留位置」，再按「重播所選小節」。後者只播放工作譜的旋律，不是原曲，也不含吉他伴奏。暫時不用判斷旋律是否準，只確認播放、暫停及位置顯示可操作。

**通過條件：** 能選八小節並對照來源；重播不把頁面跳到下方和弦區。空白音符不代表歌曲沒有旋律，請改選有音符的段落並回報空白所在位置。

## D. 小節分界：先測操作，不猜正確拍點

1. 展開「所選小節分界校正（不移動音符）」。首尾兩個分界是固定的，這是保護段落外內容，不是故障。
2. 若選 Bar 28 開始，可用 `Bar 31` 作為內部分界；先記下它目前的秒數，例如 `56.62`。
3. 將它暫改成原值加 `0.10`，例如 `56.72`。**這是可撤銷的操作測試，不表示音樂上應該往後移 0.10 秒。** 若非常接近下一小節而被拒絕，改選另一個分界，不要強行跨過下一小節。
4. 先看預覽：應顯示將改動幾個拍點，這時尚未套用。對照／定位按鈕仍使用目前已套用分界，不是輸入中的草稿。
5. 不勾「明確將所選小節內各拍等分」，按「套用小節分界」。核對秒數更新。
6. 按 `Undo`，核對回原值；按 `Redo`，核對回修改值。雖然輔助名稱可能提到 melody edit，這組 Undo／Redo 共用整份工作譜歷史，小節修改也適用。
7. 再按一次 Undo，把純測試的 +0.10 秒還原。若你能從原曲確認真正的分界，再另行填入；不確定就保留原值。

**通過條件：** 預覽、套用與撤銷一致。這個功能調整格線，不平移旋律、和弦或歌詞；音符換算出的拍長／顯示位置可能改變，但原秒數不變。若提示缺拍／尾端不完整，改選中段完整小節，不是重新分析的理由。

## E. 修改一個既有音符

1. 暫停播放。點六線譜上的一個「品格數字」，不要點空白弦線（空白是新增模式）。
2. 下方應顯示「譜上選音：…」及 `Apply note`，而不是 `Add note`。先記下原弦、品格與起訖時間。
3. 先只改品格，例如原本第 2 弦第 1 格改成第 2 格；不要同時改時間。可按「預聽音高」，但此時仍只是草稿。
4. 按 `Apply note`，確認譜面數字更新。按「重播所選小節」，確認能試聽；這是在測修改有生效，不是在宣稱新音比較準。
5. 按「暫停，保留位置」，Undo 回原音，再 Redo 確認可恢復。
6. 可選做音長測試：選一個後方有空間的音符，改「音長」為八分或四分，按 Apply note。若出現與下一音重疊的提示，先取消這個試改或選更短音長，不要刪除其他音符來硬湊。

**通過條件：** 草稿與已套用狀態分得清，品格／音長修改、試聽、Undo／Redo 都一致。原曲與 Contour 不會因人工修改而改變，請用「重播所選小節」聽工作譜。

## F. 另存、載入與重新整理

1. 可以保留一個明確知道是測試用的修改，按 `Save new revision`。
2. 記下新版本 ID，標為「B：操作測試版」；確認不同於基準 A。
3. 按 Undo，確認畫面回到修改前；再將版本 ID 填為 B，按 `Load melody revision`。應恢復 B 保存的修改。載入會替換目前工作譜，**不要在有未保存真實修改時做這一步**。
4. 確認已保存後，重新整理網頁。若出現原分析，不代表 B 遺失；在版本 ID 填 B，再按 Load melody revision。
5. 核對修改過的音符及小節分界是否與 B 一致。若想避免把故意改錯的測試版本當成果，最後載入 A，或另存一個整理好的正式修訂。

**通過條件：** A、B 可分別載入，B 的修改跨重新整理仍保留。Undo 歷史不要求跨重新整理保留；保存的修訂才是持久版本。

## G. 譜面顯示與可選匯出

1. 展開 `Melody & Tab previews · Experimental`，往下找 `Notation & Tab`，等待譜面出現。
2. 確認不是只有白框，能看到 TAB／六線、品格與和弦。若有跨小節／跨和弦的長音，可觀察延音線；没有長音的段落不必硬找延音線。
3. 本輪先檢查「有沒有畫出來、符號是否明顯錯位」，不要求每個辨識音符都與原曲一致。
4. 將瀏覽器視窗縮窄，確認預覽框不把整頁撐到畫面外。譜面內容若較寬，可以在預覽內水平捲動。
5. 可選：按 `Download MusicXML` 與 `Download MIDI` 留存。若本來有讀譜軟體可打開查看；不必為本輪另裝。兩種檔案都反映目前工作譜，匯出本身不等於保存 revision。

**通過條件：** 譜面可見，窄視窗可操作。若空白或有 Notation preview unavailable，請連同訊息、瀏覽器及截圖回報。

不需要為這次測試特別安裝第三方讀譜軟體。MusicXML／MIDI 可下載留存，但譜面沒有經過實曲完整驗收；不要用它判定來源旋律已辨識正確。

## 回報三點即可

- 八小節的定位／修改是否順手？哪一個操作仍容易迷路？
- Undo、另存與載入後，修改內容是否保持一致？
- 譜面是否可見、有沒有位置或音長明顯不合理的地方？可附截圖與小節號。

## 後續界線

本輪不宣稱八小節合奏編輯全部完成：旋律編輯器的重播仍是旋律試聽，完整旋律＋伴奏仍由 Compiled score playback 控制。後續需把段落合奏更直接整合到編輯區，並處理和弦事件時間編輯。自動辨識問題保留 #2，未關閉。
