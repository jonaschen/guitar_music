# Codex：MVP 實驗與上線計畫

使用者最新目標：最大效率使用免費額度排除問題，讓 MVP 上線。維持獨立產品、主旋律凍結；不將「只能播放指定範例」改稱任選歌曲 MVP。

## 交付內容與上線判準

第一版主流程固定為：手機／桌面貼 YouTube 連結 → 分析 → 看小節和弦、播放原曲＋吉他跟彈 → 必要時少量修正、保存與復原。UI 不再增加一排研究工具；錯誤或未知要可理解且可恢復。

發布前逐項記錄：

1. **音樂**：已接受控制組沒有退步；已知半速、第一拍錯與漏掉和聲的案例不能只因工程通過就宣告修復。拍點、第一拍、和弦名稱／時間、刷奏分開驗收。不靠換和弦觸發刷奏，不把未確認拍格畫成正式小節。
2. **跨曲**：固定既有15錄音作回歸，不稱未知測試；至少另外固定兩份未用來改規則的錄音作確認，不能選看起來最容易成功的結果。自動檢查覆蓋完整曲目，最後必要人耳集中2–3段，不要求使用者重聽整批。
3. **可用性**：手機短網址解析、原曲＋吉他、點和弦定位、修一個和弦／拍長、Undo／Redo、重載皆有自動流程驗證。首次使用不需理解模型／候選名稱。
4. **服務**：有常駐部署、健康檢查、重啟恢復、資料備份／還原及回退版本。現有家用電腦＋ngrok受邀站會隨休眠離線，不能當作完成常駐上線。現有容器配置仍須實際啟動驗證；若需付費主機，完成配置與測試後再提出具體成本，不代購。
5. **發布聲明**：可先提供有明確限制的受邀 beta，但必須逐項列未解問題，不把它寫成任意歌曲都可靠。失敗只回一長排和弦、讓不擅抓歌的人自行重建拍格，不算主要情境完成。

本表是執行順序與發布檢查，不是已達成的準確率或完成日期保證。無逐拍／逐和弦標註的使用者曲目仍不報虛構正確率。

## 免費額度使用規則

- 已完成首批6個工作：3個公開授權15秒片段，拍點與 major-minor 和弦各一次。使用者確認新註冊、沒有購買方案；未設定付費方案或同意超額。帳戶餘額未知，不宣稱還剩44次。
- 每輪在看結果前寫下唯一問題、固定輸入雜湊、唯一變因、成功／失敗分支與工作數上限。結果、失敗和API job均保留；建立工作不自動重試。
- 只重用這三份已授權音訊做下一輪詞彙對照，不上傳使用者YouTube歌曲或專案資料。新增來源須先確認授權範圍。
- 不花額度重跑拍子已失敗的同設定，不把三首混音任意串成一首節省請求，不裁到只剩成功的片段；這些做法會破壞可比較性。
- 付費／超額／額度不足回覆立即停止；後續本機診斷可繼續。外部工具只供研究驗證，不加入產品執行依賴。

### E1 的事前規則

保持三片段0–15秒、取樣率、聲道、音量完全一致，變因只有API的`vocabulary`。保留E0的拍點結果，不請求第二次。

- 主比較：Funk3可評大／小和弦的區間，full的majmin需比原結果增加至少0.15；特別列出0–2.143秒C#min7被讀成C#maj的區間。
- 控制：SS2、Rock1的root與majmin各不得下降超過0.02；Funk3的root不得下降超過0.02。
- 同時報切分密度、漏和弦秒數、未評分秒數；不得用更高的局部major/minor分數宣稱全譜正確。
- 未滿足任一條就不選full為共同設定；不再微調詞彙或只保留獲益那首。通過也只是外部診斷選項，不成為產品預設或真值。

### E0 的重要限制

Funk3中power chords缺少第三音，大／小和弦指標只涵蓋整段28.6%；SS2也僅72.7%。它們需要另外看根音及和弦組成，不能把排除的區間算作正確。此涵蓋率是在E0後核對發現，已修正評分報告，不回頭修改E0的判準或分數。
