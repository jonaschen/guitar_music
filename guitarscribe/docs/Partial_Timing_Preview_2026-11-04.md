## 固定規則

政策 `observed-local-bars-v1`，不重新跑模型、不增刪拍點、不改和弦，也不修改已接受的 `fixed-dbn-recovery-v1`：

1. 僅使用已保存 `timing-recovery.json` 的 primary／candidate；兩者來自同一模型，**不是兩個獨立模型的正確性背書**。
2. 原始相鄰重拍間有 3 或 4 拍，且完整落在音訊範圍內。
3. 原始拍點及重拍，與候選一對一匹配，差異不超過既有 70ms；沒有插拍、刪拍或換重拍相位。
4. 拍距相對全曲中位數仍使用既有 `(0.6, 1.75)` 開區間。另在相鄰拍距突然跨此比例時切開，防止兩種密度數量相等、全曲中位數落在兩者之間而掩蓋突變。此項由合成反例觸發，不是針對新歌調參。
5. 同拍號連續至少四小節才展示；不跨缺口延伸、不推算未知小節數、不補到音訊結尾。

這些規則只能篩除已知結構／密度風險，不能判定音樂上的第一拍一定正確；真實變速也可能被保守排除。原本完整可用的小節譜不使用這個預覽。

## UI 與資料保護

歌曲頁新增「預覽可辨識的小節」；原時間表仍是預設，可隨時切回。分享網址加 `timingView=partial` 可直接開預覽。點和弦仍從該實際時間播放；跨小節延續顯示延續記號，休止與未知區間保留。

預覽沒有把局部拍格寫入工作譜，因此吉他仍按原和弦事件播放，不能宣稱已套用規律小節刷奏。進入編輯會回到時間表，避免讓使用者誤認為只改了一個小節、實際卻改整段延續和弦。改名／復原後預覽讀取目前工作譜，不回寫舊分析。

新 API `GET /api/v1/jobs/{job_id}/timing-preview` 僅讀已完成 job 與固定檔名的證據；不啟動推論或保存。來源 job、音訊長度、裁切起點必須和目前譜面一致，前端才採用；切歌取消舊請求。缺少舊診斷、資料損壞或不同裁切時，保留時間表，不阻斷歌曲。
