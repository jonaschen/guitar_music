# A21：限定調內候選的單變因驗證

2026-11-06，Codex 顧問制定。使用者明確要求先排除調外和弦，簡化目前問題。這項新決策授權獨立簡化候選；原稿、人工修改與線上預設保留。

## 先驗證哪一步

先只測「限制調內候選」能否改善，而不一次加入 I／IV／V 行進權重、假定起終點為 I、每小節只准一個和弦或改拍格。後者需要前一步及可靠小節／樂句證據。現有 Chordino 有 HMM 連續性解碼，但調性在辨識和弦後才估計；舊 chromagram 引擎已有調性／五度關係偏好，不能把它們當成全新且已證實有效的方法。

與 A12 不同：A12 否決的是降低共同 self-transition 的理由；本輪完全保留原 HMM，只有使用者指定的候選資格限制。不是重跑舊平滑調參。

## 固定來源與調性

- 全部沿用 A12 九份 trace：六份 GuitarSet 控制與 HU33_04／18／21 混音目標；不挑曲、不改 A09 已固定的參考時間域／offset。它們是已使用的開發來源，不能叫未見測試集。
- 重用 `output/evaluation/chord-decoder-trace-2026-11-05/` 的 217-state dictionary、emission、timestamps、原 path，核對原 run-result／A10 input plan 的 hash。零音訊推論、零外部上傳／下載、零模型更換。
- 調性只從原版事件經**現行** `estimate_key_from_chords` 計算一次並凍結，不隨候選反覆估計、不讀 reference key、不從檔名選調。六份舊 GuitarSet score／raw cache 的 key 都寫 C major，不能直接當目前估調結果：需從同版 baseline 原事件按現行 audio-intersection 解碼後計算，記錄舊值與本次固定值。
- 固定原推估調性可能錯誤，這是本方案真實限制；不得看到分數後以人工／參考調性替換補考。最新兩首使用者歌曲只作 UI／症狀紀錄，不混入本次準確率。

## 唯一候選規則

1. 大調音級集合為 tonic+[0,2,4,5,7,9,11]。小調分別列自然小調 [0,2,3,5,7,8,10] 與和聲小調 [0,2,3,5,7,8,11]，一個 profile 的全部音必須完整落在其中**一個**集合；不是把兩集合合成八音集合。這是事前固定的小調定義，保留常見升導音屬功能；不另加旋律小調或其他例外。
2. 根據字典實際 24 個 bass／treble 權重的正值音級決定是否調內，bin0 是 A（pitch class9），不是 C。非 N profile 必須非空且全部音級符合上述條件；不只看根音、不刪除轉位低音。保留重複標籤不同 profile 的原 index，不擴字典。
3. N 狀態永遠保留。只把不合資格 profile 的 emission 設為0；保留其餘原值，不重新套另一分數或平滑。不刪 state、不改原217×217矩陣：self=.99，off-diagonal=(1-.99)/216（沿用作者浮點運算），初始N=1。所有 frame 使用原 timestamp，不重採樣或外推。
4. 呼叫本機已固定作者版 `viterbi.cpp`，先用未改 emission 重播，九份原 path 必須**逐 index 完全相等**。不可只比根音或平均分；若失敗停止，不以新解碼器當 baseline。
5. 按原 `Chordino.cpp` 的狀態變化／最後N事件規則還原輸出。baseline 還原須與 A12 raw events 核符，再沿相同 decoder／原有投影規則得到可評稿。候選禁止選到 excluded state；數值或來源不符即工程失敗。

限制候選可能連帶改變解碼邊界，需照實量測；不能宣稱只有標籤變了。完整音訊、基準稿與人工修訂皆不得寫入。

## 評估與停止條件（看候選結果前固定）

- 使用既有獨立標註及相同全時間域評分；所有 baseline 有標註秒數都保留，候選N／漏和弦不能從分母移除。分開 root、majmin、漏／多和弦秒數與邊界 precision／recall。
- 記錄每份固定key／mode、保留profile數、改變標籤秒數、N增減、被排除的參考和弦秒數，以及基準正確→候選錯誤／反向修正秒數。後兩項只作評估，不回饋修改候選。
- 繼續條件須全部成立：三份HU33 root等權平均至少+5百分點、至少兩份各+5百分點；九份每一份 root與majmin都不退超過2百分點；每份漏+多和弦不增加超過0.25秒、邊界precision／recall不退超過5百分點；參考覆蓋與時間域不變。
- 任一音樂護欄未過：停止這組固定自動調性＋調內硬限制，不調key、不放寬門檻、不加入行進權重混成下一版本、不交新的使用者A/B。這不等於否定人工指定正確調性或所有功能和聲方法。
- 全過：僅取得下一次獨立確認的資格，不直接改線上預設；需要另外固定未用來調規則的錄音，及有必要時一次人耳驗收。

## 執行界線

最多60分鐘，自首次 replay manifest 記錄時間起；單進程／最多2 CPU、全部快取解碼，零新的模型推論。事前保存本文件、runner、作者Viterbi來源、trace／原始事件與評分來源hash；結果另存新目錄，不覆寫快取。先過必要的音級映射、大小調集合、N保留及baseline重播工程閘門，才產生候選數值；完畢提交／推送程式、精簡數值和報告，顧問獨立審查。若時間到或工程失敗，保留具體阻塞，不用未完成結果宣稱品質。
