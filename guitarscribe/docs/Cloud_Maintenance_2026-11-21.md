# 個人雲端：保存、備份、保留與費用檢查

此改版已部署至個人雲端；正式版本以 deployment.json 與服務實查為準。本次資料保護與發布結果見 [改版紀錄](Cloud_Update_2026-11-21.md)。

## 使用者會看到什麼

原頁面的「已保存」表示練習稿已寫入主機。頂端「保存與備份」另列最近完成時間與備份狀態，避免把兩者混為一談。

| 狀態 | 意義／處理 |
| --- | --- |
| 已完成備份 | 已驗證完整 manifest，且沒有觀察到之後的練習 DB 修改。不是持續同步保證。 |
| 新修改等待備份 | 最近成功快照之後又有 DB／WAL 修改，等待下輪 timer。 |
| 正在備份／延後 | 上傳中，或分析／另一備份尚在執行。原進度仍可保存在主機。 |
| 失敗／中斷 | 最近一次未完成；保留先前成功時間，不以失敗時間取代。請檢查 timer 日誌、磁碟、權限與網路。 |
| 無法確認 | 未安裝、尚無紀錄、紀錄損壞或連線失敗。不能當已備份，也不等於原稿遺失。 |

備份每輪啟動約15分鐘後開始，運行中約每30分鐘執行；分析會延後，主機休息不運行。最近完成時間可能晚於實際快照時間，不代表之後修改已包含。多個 SQLite 透過各自 backup API 一致拷貝；整個 workspace 不是跨資料庫單一交易。

## 維護介面

- 登入後 GET `/backend/cloud/maintenance` 只回傳狀態、時間與磁碟可用量，沒有音訊、歌名、密碼、檔案路徑或 exception 內容；同既有 gateway 認證。
- `/srv/guitarscribe/maintenance/backup-status.json` 為持久且 mode 0600；不放入 work，重開機仍能辨認中斷。超過20分鐘的 running 不當正常執行。
- `backup_work.py backup --status-file ...` 以 flock 防止另一呼叫覆蓋正在執行的狀態，atomic replace/fsync；上傳完整 manifest 並驗證後才記 complete。
- 新 API 是讀取，不維持使用活動。原可見頁的 heartbeat 依原規則運行。停止主機後不為查狀態自動啟動。
- 空間低於3 GiB顯示提醒；這是維護門檻，並非所有大型新歌都能安全處理的保證。

## 備份保留策略

目前保留**所有完整快照 manifest 及其內容定址 blobs**。相同音訊以 SHA 去重；每天重複備份不重傳相同音訊。未成功的上傳可能留下無 manifest 引用的 blob，目前也保留。

不設桶層按天刪除：新的 manifest 可能引用很久以前的音訊 blob，單純刪舊物件會破壞較新的完整備份。應用服務帳號沒有 delete／覆寫權限。

每月先檢查桶容量與新增用量。若需縮減，準備可審閱的清理清單：保留全部近31天快照、每週一份到12週、每月一份到12個月，以及手動釘選的還原點；永遠保留至少最近兩份可驗證的完整快照。計算所有**保留 manifest** 引用聯集後，才把未引用且超過7天的 blobs 列為候選。先還原驗證最新與最舊保留點，再在使用者已授權的具體範圍內刪除。現階段沒有自動垃圾回收，也未刪使用者備份。

## 費用檢查

40小時／31天與每輪2小時限制為運行護欄，不是新台幣300元硬上限；usage含預留，不等於已開帳。

每月檢查 Google Cloud Billing Reports，使用 hanana-491223 專案篩選，再核對 GuitarScribe 的 Compute VM／磁碟、Cloud Run、Cloud Storage 和流量；同專案另有其他應用，不能直接把專案總額當 GuitarScribe 支出。記錄實際日期區間、幣別、已發生成本、預測與共享額度歸屬。沒有當期帳務證據就標「未確認」。費率或匯率若要重新估算，查當下官方來源。

維護 skill 的 `cloud_status.py` 能讀 VM、gateway、時數與完整備份物件列表；不會啟動主機、不讀私人歌譜、不重設帳本。它不是帳務查詢工具。實際月帳單與真實長期使用證據仍需時間累積。
