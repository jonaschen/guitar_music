# Codex：最後旋律驗收門檻與收尾計畫

決策日期：2026-10-27。依使用者最新指示，優先於先前外部工具、整合與無期限研究建議。

## 目標與停止條件

- 第一驗收點：主旋律拍長正確程度至少 95%，旋律正確程度至少 85%，兩項皆需滿足。旋律正確程度先按音高與旋律走向理解；拍長包含音符長短、起訖及休止是否自然合拍，不能只看檔案總長。
- 達標即收束這一階段，不再為追求滿分擴大旋律研究。
- 「超過星期三」按本地 Asia/Taipei 解讀為 **2026-10-28 23:59:59 +08:00**；自 2026-10-29 00:00 起停止本輪旋律研發。沒有明確驗收結果也不視為通過，不因等待回覆自行延長。
- 期限到未達標：放棄本輪自動主旋律改善路線，保留原資料、候選、實驗紀錄與可用伴奏；不是刪除成果或放棄整個工具。之後進行 UI 收斂與交付紀錄。
- 獨立、本機運作。不申請 Klangio、不上傳音訊、不接外部轉譜 API。外部測試包留作歷史產物，並非待授權事項。

## 如何判定而不捏造百分比

目前沒有可信逐音標準答案；95%／85% 保留為使用者設定的門檻，不能用模型 confidence、短音數、F0 自我一致度、通過測試數或拍格對齊率代替。

暫行驗收方式為使用者聽感判斷是否達到這兩項目標，不要求使用者大量逐音標註，也不把主觀估計寫成實測正確率。若需嚴格統計正確率，必須另有獨立校對的音符與起訖參考；現有網路參考譜只能提供弱參考。未有依據時寫「未量測／未確認」，不得宣稱達到數值門檻。

比較沿用既有固定視窗：第三來源原曲 20–40 秒、40–60 秒，以及小手保存 G 的既有約 14.466 秒片段。工程先核對時間原點、來源、聲部及排程，再交付簡單試聽；各片段結果分開記錄，不挑最好片段冒充整體結果。首個驗收點的證據範圍限於所測片段，不外推所有歌曲。

## 期限內的工作界線

1. 先查歷史停止條件，提出有不同證據或機制支持的本機假說，凍結比較片段與失敗條件；不重跑已失敗方法湊版本。
2. 工程檢查、版本保護、來源核對、播放一致性由 Codex 完成。只有值得比較的音樂品質候選或 UI 人類驗收才交使用者。
3. 不把伴奏拍格整理直接套在主旋律，亦不為減少零落感而無依據地刪短音、填休止或改音高。
4. 如果沒有可辯護的新方案，可提早停止，而非為用滿期限持續試驗。未承諾已有可達標的方法。

## 旋律工作結束後：UI 與交付

使用者明確說明：主旋律最初主要是為了驗證和弦；現在「原曲＋系統吉他」已能支持這個用途。因此旋律不再是整個專案收尾的無限阻礙。

- 主流程收斂到來源分析、原曲＋吉他對照、選段／循環、和弦調整、保存與匯出；保留簡單對照方式。
- 旋律若達標，保留清楚入口及適用範圍；若未達標，明示實驗狀態並移至進階區，不刪除使用者既有旋律與修訂，也不把它當主要流程必需步驟。
- 將日常操作與診斷／歷史實驗分開；重要還原、保存及目前版本狀態就近顯示。
- 自動回歸完成後，只交一次簡短 UI 人類驗收，不讓使用者代做機械性測試。
- 收尾紀錄包含已驗收功能、來源／片段限制、未解問題、啟動與測試方式、保存／還原方式、必要本機產物位置及最終 commit；保持 commit & push。
