# Codex：跨歌曲固定規則檢查與《你的樣子》定位

日期：2026-11-02。使用者最新方向：開始大量嘗試不同歌曲，避免為單曲反覆調參。主旋律維持凍結。

## 本輪結果

新增每次分析完成後自動保存的 `analysis-health.json`，以及唯讀批次盤點工具。這是工程觀察，不是音樂準確率，也不會替使用者刪和弦、修改拍點或覆寫歷史聽感判決。

固定政策 `cross-song-health-v1` 記錄：

- 模型／參數來源、工作譜 SHA256、拍格是否成立及拒絕原因。
- 每 10 秒的拍距中位數；至少四個間隔才計算。相鄰有效視窗的比值在 1.8–2.2 或其倒數時，記錄約倍速／半速的密度變化。這也可能是真實速度變化，不當成錯誤定案。
- 和弦數、短於 0.5／1 秒的數量、未能解析完整指型的和弦。
- 實際吉他排程事件、單音事件、沒有刷奏起音的和弦。沒有起音可能來自選用的節奏，並不直接表示播放故障。

診斷寫入失敗只留下警告，不丟棄已完成的分析。無拍格歌曲的被拒拍點僅作觀察，不灌回譜面。

新 YouTube 分析同時保留來源網址與下載所得標題，修正本機 WAV 分析後標題變成 `input`、失去來源身分的問題。沿用同一次下載，不增加一次查詢。舊工作譜不批次改寫。

## 新曲不是密集短和弦的同一個問題

來源：[《你的樣子》翻唱版本](https://www.youtube.com/watch?v=RX5Sex2LFgk)，job `e9bfab84ed9d49bf88b9be2753353c94`，209.142 秒。

| 觀察 | 結果 |
|---|---:|
| 和弦數 | 68 |
| 短於 1 秒／0.5 秒 | 4／1 |
| 和弦長度中位數 | 約 3.065 秒 |
| 吉他事件／單音事件／沒有起音的和弦 | 68／0／0 |
| 原始拍點／重拍點 | 285／68 |

原始重拍間隔混有 1、2、3、4、5、8、9 個拍點，未通過小節結構檢查。前後約 0.48 秒與 0.96 秒的拍距交替，因此目前顯示時間表，每列是一段和弦、每段彈一次，並不是把整列誤當成小節。

只做了一次既有設定的解碼對照：同權重、同逐影格輸出，固定預設 DBN。得到 252 拍／63 重拍，通過 4/4 結構檢查，但約 31 秒後仍從 0.48 秒轉為 0.96 秒。**結構合法不代表音樂拍格正確；不升為新歌預設、不覆寫此工作譜。** 未做新一輪調參，也沒有此曲人耳拍格驗收。

解碼資料：`output/evaluation/new-song-decoders-2026-11-02/e9bfab84ed9d49bf88b9be2753353c94/`。來源標題同次下載驗證：`output/evaluation/source-identity-smoke-2026-11-02/`。這些本機音訊／診斷檔不加入 Git。

## 跨歌曲基準與後續方法

兩個既有工作區共有 38 次分析紀錄：23 次完成、15 次失敗；完成者 10 次有拍格、13 次退回時間表。包含重複來源、不同裁切與歷史失敗，**不是 38 首獨立歌曲，更不是成功率或準確率**。明細保存來源網址、裁切設定、工作 ID 與原 payload SHA256；人工回饋繼續留在原驗收文件。

本機固定快照：`output/evaluation/song-batch-2026-11-02-final/report.json` 與 `report.md`。

重新盤點的命令（使用新的輸出目錄；已有目錄會拒絕覆寫）：

```bash
cd guitarscribe
python backend/scripts/audit_song_batch.py output/evaluation/song-batch-NEXT \
  output/web-preview/work output/work
```

下一步沿用正式分析設定增加不同曲目的實戰樣本，依「取得來源／拍格／和弦標籤與切分／刷奏／顯示」分類，不先按歌名、鋼琴或吉他伴奏配置專用參數。來源型態目前僅是假說。

有共通失敗證據才提通用修正：先固定規則，在失敗例與已接受的其他來源一起檢查；工程通過後再集中提供必要的人耳比較。不可把單曲較順就當成跨曲通用，也不可只用短和弦變少或結構合法宣稱改善。

使用者照常選歌、播放原曲＋吉他與跟彈即可；有問題只需回報歌曲及大約秒數，描述「拍子／換和弦／漏刷／畫面」或「不確定」皆可。不要求逐音標註或重驗已接受的拍子。
