# 中斷分析恢復、和弦級數與 Capo 按法

本次程式與測試已實作；雲端是否已更新、實際版本及驗證結果以 [維護交接](MAINTENANCE_HANDOFF.md) 為準。

## 上傳中斷後繼續

已上傳的音檔若分析失敗或被取消，且伺服器仍保留來源，畫面會提供「用保留音檔重新分析」。按一次建立新工作，使用原本選項和標題，從頭重新分析；原歌、根音、結構與和弦稿保留。

如果按下後回覆中斷，再按同一來源的按鈕會找回同一個新工作，避免重複排隊。新工作再次失敗時，才從新工作再次重試。音檔已遺失、YouTube 下載被拒絕、正在分析或已完成的工作不提供這種恢復；仍可重新選擇音檔。

分析畫面顯示當前階段、已經過時間及最近更新。排隊也算等待時間。它不保證某個百分比或預估完成時間，重試也不是接續某一模型的計算斷點。

## 看已填和弦的級數

1. 開啟已鎖定段落的和弦練習，選擇要看的 A–B。
2. 展開「主音與調式假設」，選自己的主音與大調／小調。尚未確定時繼續保留未定即可。
3. 展開「用級數理解這段和弦」，由「實際和弦名稱」切換為「羅馬級數」或「數字級數」。原名稱一直保留，例如 C 大調的 `Am → vi`，數字顯示 `Am → 6m`。
4. 假設尚未保存時明示「試算」。若要下次保留假設，使用原有「採用並保存調性假設」；切換級數顯示本身不保存或改寫和弦。
5. 局部假設只用於原先固定的錄音範圍，移動 A–B 不會把它延伸到其他地方。超出範圍時提示沒有可套用區段。

本工具採「主音為1、同主音大音階為比較基準」：A小調的 Am、C、F、E7 分別是 i、♭III、♭VI、V7。這是刻意選定的讀譜慣例；小調也有其他級數慣例，不能混用。[de Clercq 的音樂理論研究](https://mtosmt.org/issues/mto.21.27.4/mto.21.27.4.de_clercq.html) 比較了這類大音階參照與六級小調等系統。

羅馬大小寫區分大／小和弦，°為減、ø為半減、+為增。C/E 另外列出低音 E 及其級數，不把低音當和弦根音，也不推斷古典轉位或次屬功能。加六和弦使用 `I(add6)`，避免與代表轉位的 `I6` 混淆。數字顯示是這個工具的簡化記號，不宣稱完整 Nashville 譜格式。

未填和弦顯示待聽，N.C. 保留無和弦，不支援的複雜符號保留原名稱。來源或版本有衝突、調性未定／其他時不換算。這裡沒有新的聲學辨識，不發聲、不移調、不從根音補答案，也不代表已證明音樂功能。

## 比較較容易的 Capo 按法

主畫面的和弦譜下方，展開「比較較容易的 Capo 按法」。填建議最高 Capo，以及選填的偏好把位（從 Capo 起算），按「比較按法方案」。偏好把位是柔性排序，不強迫每顆和弦停在同一品；最高 Capo、最高琴格則沿用目前吉他設定的上限。

方案先比較完整和弦覆蓋，再比較整段按法難度、前後換把成本與偏好把位差距；無和弦、缺按法或不連續時間會切開換把路徑。只有根音的備用按法不算完整和弦，不支援的slash／延伸和弦會明示不足；未完整覆蓋的方案不能直接採用。非標準調弦不套用這套標準調弦指型。

按「採用 Capo …」才把該方案的Capo及實際按法路徑套用到目前工作譜，使用原有保存、復原與重開流程。原和弦的發聲名稱與錄音音高不變，來源版本及獨立根音／結構稿保留。比較期間改設定或工作譜，舊結果不會拿來採用。

換把成本沿用專案指型最佳化的手位／共同音啟發式，負值截為零；偏好品格距離每品加0.08。各項加總後按有效和弦事件數平均，完整覆蓋優先於分數；它是可重現的工程排序，不是經真人標註校準的演奏難度。手型、速度及個人習慣仍可能改變你的選擇。

## 已做的驗證與界線

- 取消排隊、重複取消背景工作、保留上傳重試及超限清理都有先失敗後修正的回歸。
- 重試使用真實 API 與臨時工作庫，在 Chromium／Linux WebKit 驗證丟失第一次回覆、重試去重、重開、原稿不變與音訊 Range。
- 級數字典驗證音名拼寫、調外和弦、大小／減／半減、延伸音、獨立低音、未知保留。兩種瀏覽器驗證實際保存資料不因顯示切換而改變；WebKit另驗局部範圍不延伸。
- Capo先取得六個失敗回歸，修正不完整指型、上限、無和弦、換把、偏好把位及slash覆蓋；與轉調／指型共221項後端回歸通過。API長計算不阻塞health；UI不完整方案禁採用，較舊設定回覆不重現。
- Chromium與Linux WebKit使用真API選擇Capo方案、套用其實際指型ID、保存新版本並重開；和弦發聲名稱／時段與原版本完整保留。恢復與Capo共4項真API瀏覽器測試通過。
- 這些不是實體 iPhone 測試或真實歌曲辨識準確率。長時間測試結果與正式發布另記於交接文件，不因短測通過就宣稱全部穩定。
