# GuitarScribe：分析初稿、人工修譜與回饋分析

日期：2026-09-30。依使用者最新產品方向調整優先序；以下包含規劃及第一個已實作、待人工驗收的 checkpoint，不代表整體完成。

## 第一版實作狀態

已提供獨立旋律編輯器：8 秒聚焦、音高／八度、起迄秒數、增刪、切分與合併相接同音。空分析也能補入音符。修訂片段可單獨試聽，Undo／Redo、保存新 revision、重載及各匯出沿用工作樂譜；刷新後可找回最後保存 ID，再明確載入。操作及限制見 [測試說明](Melody_Editor_Checkpoint_2026-09-30.md)。

每次旋律編輯保留 before/after、操作、時間、來源 job（已知時）、移調量，意圖固定為未分類；保存分支保留父 revision。尚無完整來源指紋／意圖審核、鎖定、參考集合或重分析。原 job、F0 與來源音訊不修改。下方較廣的驗收項目仍保留未完成狀態，避免把秒數編輯誤算為完整拍位編輯器。

## 產品目標

準確且充分地分析歌曲的和弦、主旋律、節拍／小節與樂理，產生可聽、可讀、可修、可匯出的樂譜初稿。主旋律包含主唱及樂器接手的段落，不等同於人聲音高。

不以全自動零錯誤為編輯功能上線的前提；也不以「可以手動改」替粗糙或漏掉大量內容的分析開脫。先讓使用者完成作品，再用可追溯的修正逐步改善分析。

核心流程：**分析初稿 → 對照原曲 → 人工修正 → 試聽／保存／匯出**。

後續選用流程：**確認修正作為參考 → 局部重新分析 → 比較差異 → 使用者接受或拒絕**。即使不重新分析，第一個流程也必須獨立可用。

## 資料與播放原則

1. **原始證據不動**：來源音訊、分離音軌、原始 F0、候選與原始分析保留。
2. **可編輯譜面獨立**：修正後的和弦、音符、拍長、指型形成工作版本；使用者可撤銷、保存新版本、重載。
3. **播放名稱不混淆**：Original／Vocal contour 是原始來源對照；Edited score／Play score 才呈現人工修譜。不可讓使用者改了譜卻一直聽原始 contour，誤以為修改沒生效。
4. **記譜不破壞輪廓**：保留已較準確的連續音高作底圖／試聽證據。現有離散音符解碼未通過，不得宣稱輪廓可辨認就等於 MIDI／Tab 已正確。
5. **實際時間與拍位分開**：支援自由時間修改及明確選用的拍點吸附；不強迫錯誤 beat grid。TempoMap 未可靠前仍顯示原曲秒數。
6. **修正優先保護**：重新分析輸出新候選／分支，不能自動覆蓋使用者確認或鎖定的內容；移調／Capo／編曲變更不是原曲辨識真值。

## 第一優先：可獨立完成修譜的編輯流程（QR4＋QR5；M3／M4 資產）

- [ ] 音符選取與小節／片段聚焦，不再把整首密集音符擠在同一屏。
- [ ] 修改音高／八度、起點、終點／拍長；新增漏音、刪除誤音、切分／合併同音。
- [ ] 沒有可用候選時也能新增或替換一段，不依賴失敗的舊音符初稿；不要為了顯得完整而虛構音符。
- [ ] 空白／休止與「尚未辨識」分清楚，使用者可確認該段沒有主旋律。
- [ ] 原曲 A–B loop，原始輪廓與修訂譜面試聽可切換，明確標明目前聽哪一版。
- [ ] 修改納入 Undo／Redo，標記人工來源；不能因 `edited=true` 就把模型 confidence 改成 1。
- [ ] 保存／重新載入與來源 job 的對應；保存入口不依賴必須先選一顆和弦。
- [ ] 修訂後的 Play score、MIDI、MusicXML、Tab 使用同一組修訂音符；重新計算受影響指板配置，不保留舊音高的弦／格。
- [ ] 在時間非法、越界、重疊或吉他不可彈時提示處理選項，不悄悄刪音或改成另一個音。

第一 checkpoint：使用者在一個 4–8 小節片段中改錯音／拍長、補漏音、刪誤音，能立即聽到修改；Undo／Redo、保存重載及匯出保持一致。此時不需要重新分析，更不需要先解決整曲自動辨識。

## 第二優先：把修正變成可追溯參考（QR0＋QR5）

- [ ] 編輯紀錄包含：來源指紋與 job、原分析版本、父 revision、事件 ID 或時間範圍、操作、before/after、原曲時間、顯示 Key／Capo 與使用者意圖。
- [ ] 刪除、切分與合併也需記錄；不能只保存目前剩餘事件的 `edited` 旗標。
- [ ] 意圖區分「修正辨識」「編曲／簡化」「未分類」；未分類預設不加入原曲正確答案集合。
- [ ] 另外確認某段為可用參考，並可撤銷確認／解除鎖定；編輯過不等於人工已完整審核。
- [ ] 比較分析初稿與核准參考，找出音高／八度／起音／拍長／和弦／小節位置的錯誤類型。
- [ ] 先限同一首歌／同一來源範圍內使用；不宣稱保存修正就會自動訓練模型，不自動上傳或跨歌曲套用。

驗收：同一片段修正後能追溯原始答案、修改原因及差異；分析錯誤與創作性編曲不混為評分基準。

## 第三優先：有人工約束的局部重新分析（QR2／QR3／QR4）

- [ ] 選擇範圍及要重算的層：拍點、和弦、旋律或來源路由；使用足夠前後文，但僅提出目標範圍內的修改。
- [ ] 可引用已確認的音符、和弦、小節起點、來源類型及明確設定的調性作參考／約束。
- [ ] 候選與人工鎖定衝突時列出差異，不為了滿足模型或樂理規則偷偷改鎖定內容。
- [ ] 重分析結果存新分支，支援前後試聽、逐項接受／拒絕及復原；失敗保留原工作版本。
- [ ] 固定使用的模型／設定／參考 revision，避免過期回應覆寫新編輯；保留快取與來源證據。

驗收：使用者修正的區段保持不變；新候選只在選定範圍提出，能說明參考了哪些修正。是否真的更準須另做聽驗，不能用「遵守約束」冒充辨識改善。

## 分析能力持續推進：充分覆蓋歌曲與樂理解釋

- 人聲主歌錯誤與器樂接棒分開驗證；維持已接近的副歌，不作全曲盲調。
- 標示 Vocal／Instrumental lead／No melody／Unknown 的區段意圖；來源切換不能單憑 pYIN voiced probability 或音量決定。
- 和弦、旋律、低音、調性、節拍與樂句互相提供證據；五度圈／功能和聲解釋行進，CAGED／voice leading 幫助吉他編配。
- 區分「偵測到的聲響」「樂理解釋」「建議編配」。非調內和弦、經過音、借用和弦或轉調不能只因不符合常見規則就被刪除。
- 理論建議顯示依據、替代解釋與不確定性，使用者可接受或忽略。人工指定的 Key 可是分析修正，也可是移調編曲，必須保留意圖差異。

## 驗收方式調整

分別衡量三件事，不互相替代：

1. **自動初稿品質**：聲部與段落覆蓋、漏抓／誤抓、音高與時間、和弦與小節位置。仍需要核准參考及真實歌曲測試。
2. **修譜成本**：把相同片段修到可用所需時間、操作數及是否能完成；人工把整段重打不能算自動分析成功。
3. **最終作品可用性**：修訂樂譜能否接近原曲、播放與譜面是否一致、保存及匯出是否忠實。

既有 G1／G2／G3 自動品質 gate 不宣告已通過；人工可修譜作為獨立產品 checkpoint，不再被 G3 全自動辨識驗收無限阻塞。足夠準確與充分覆蓋的門檻，須用代表性片段、實際修譜負擔與使用者確認制定，不先報無依據的完成百分比。
