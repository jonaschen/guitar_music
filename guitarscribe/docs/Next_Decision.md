# Codex：首輪診斷後的唯一建議

日期：2026-10-25。證據見 [Diagnostic_Findings.md](Diagnostic_Findings.md)。

## 建議：進入一次有上限的「起訖／起音資訊」驗證

先保留目前辨識器，使用既有音訊與 contour，驗證能否把聲音的重新起音與結束證據納入音符切分。這是下一階段候選，不升級預設、不先擴建 UI。建議依原計畫單獨以4個有效工程小時為上限，並在該階段結束交付一次集中試聽。

理由：完美 F0 仍會合併相鄰同音；乾淨音訊在換音邊界會多出錯誤短音。只調整播放長度或音高平滑，沒有補足重新起音資訊，也無法保證保留合法短音和休止。這提供了比逐曲微調更明確、可推翻的假說。

## 下一段具體交付與停止條件

1. 先用已有合成正解評估一個起訖候選；必須恢復同音重奏、減少兩個額外邊界音，同時保留合法75ms音、休止、切分與跨小節長音。不能只靠音符數變少判定成功。
2. 固定參數後，在失敗job原 Bar 8–15及既有已保存G片段離線比較；查人聲stem→contour→切分結果。沒有人工真值，不報原曲準確率百分比。
3. 伴奏只準備原始和弦邊界的長音對照，以隔離刷奏與和弦邊界問題；不與旋律候選同時改和弦貼格規則。
4. 只有工程比較有支持時，交付一次簡單音檔索引，最多三組「原版／單一候選」。使用者只判斷聽感，不逐音標註，不要求在複雜 UI 操作。

若合成控制也無法改善、改善需破壞合法音符、真實片段反而退步，或到上限仍無有效候選，就停止該路線，提出外部辨識比較的具體成本與資料需求；不再無限產生字母版本。外部上傳／付費尚未發生，也不是本建議預設的下一步。

## 本次檢查點的判斷

有繼續做一個受控實驗的理由，尚無宣告整個產品可完成的證據。已修復確定的5ms編譯失真，但沒有把它稱為原曲零落感的解答。伴奏根因仍待隔離；若最終只能伴奏達標，是否接受縮小產品範圍仍由使用者決定。

本次不需要使用者試聽或驗收 UI；目前交付的是錯誤定位與下一步判準。
