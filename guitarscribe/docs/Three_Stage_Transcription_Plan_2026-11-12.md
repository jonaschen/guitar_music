# 三階段抓歌協作：主音與調式、根音、和弦

2026-11-12，依使用者在根音試用後提出的新方向規劃。本文件是下一版設計，不是已發布功能清單；目前已發布的是根音工作區及E2起的持續試音修正。

2026-11-21 實作更新：人工全曲／局部調性假設、時間筆記、組成音比較與參考聲、錄音音級能量、根音／交界變動重聽提示已部署，詳見 [現行操作說明](Learning_Practice_2026-11-21.md)。保留現有畫面中的可折收工具，不新增強制三步精靈。以下是原設計脈絡；原分析調性提示、聲學候選自動排序及羅馬數字等仍屬未啟用的設計選項，不應視為目前功能。

## 產品流程

畫面導覽為「① 找主音與調式　② 抓根音　③ 組成和弦」。這是引導順序，三步可隨時返回，也能在第一步保留未定後繼續。目標是逐步建立使用者自己的和聲稿，不要求軟體一次給出完整答案。

這裡將使用者的「主調與調性」具體拆成兩項：以哪個主音為中心，以及大調／小調等調式。第一版直接支援大調、小調、未定／其他；不把全部音樂強制歸入大小調。若同曲段落中心不同，保留局部標記與待釐清狀態，不以全曲假設抹掉差異。

## 第一步：找主音與調式

使用者選一段收束較清楚的樂句，聽原曲並比較主音參考聲；沿用低音持續試音與音量控制。主音可選十二音，也可暫未定。調式另選大調、小調、未定／其他，兩個問題分開處理。

提供原分析的調性提示，但清楚標示「由原和弦推測，待確認」。保留關係大小調作對照假設，例如C大調／A小調不能只靠音集合區分。比較音階或主和弦時，原曲保持原調，區段、音量及比較音域一致；引導聽樂句的停留與收束，不把不撞音、第一音或最後音當成單獨定調規則。

按「採用為目前調性假設」才保存。保存的是工作假設，可附依據時間與簡短筆記，不是驗證真值。不以自訂百分比當正確機率；沒有足夠資料顯示未定，不回退顯示C大調答案。

## 第二步：抓根音行進

完整沿用已發布的選段、E2–Eb3持續試音、由低到高排列、半音步進、三線索／十二音、採用／待聽、分段合併、復原與保存。頂部顯示目前主音與調式假設，隨時可返回第一步。

調性只作理解與排序線索，不刪除調外候選，也不因修改調性移調原曲或已採用根音。使用者已採用的根音保持原音級。只有根音時，可以顯示相對主音的距離或級數，但不能提早寫成已確認的I／ii／V等和弦性質。

可以先完成一個短句，再進第三步；不強迫整首逐段確認。根音未定的區段也能到第三步觀察線索，但不自動補根音或把最低音當根音。

## 第三步：組成音比較與和弦行進

同一段保留根音、原曲與前後文，呈現三層資訊：

| 層次 | 呈現與用途 |
| --- | --- |
| 錄音線索 | 分析範圍、音級能量／支持線索、使用者聽到的音及其來源；線索不足明示。音級能量不等於確定音符、八度或伴奏聲部。 |
| 候選的理論組成音 | 候選名稱、音名及級數，例如G為G–B–D（1–3–5），Gm為G–Bb–D（1–♭3–5）；這是字典定義，不冒充錄音量測。 |
| 個人採用稿 | 已採用根音、和弦性質、可選低音／轉位、待確認及依據，均須明確採用才保存。 |

先呈現少量可比較的候選；可展開完整類型。初始比較包含大／小三和弦、sus2／sus4、減／增三和弦、屬七／大七／小七與無三音和弦，按實際有支持的字典與證據處理；未知不硬套類型。組成音可逐音播放、同時合奏及和原曲比較，突出候選之間不同的音，而非只顯示一排和弦名稱。

例如根音G，G／Gm的區別是B／Bb。介面可問「試比較這兩個音」，並允許「都不確定」。若辨出低音B而上方支持G–B–D，可記G/B；不能因B最低而改根音為B。和弦外旋律音、持續低音與泛音可能影響聲學線索，均不自動判成增加和弦音。

採用後串成和弦行進，可連聽、修改與匯出。主音與和弦性質皆有工作判斷時，才提供相對級數／羅馬數字供理解；仍保留實際和弦名、來源秒數與待確認，不以常見行進強迫修正例外。

## 畫面安排

沿用白底、藍色選中狀態與大音名，維持同一首歌、同一段與同一播放時鐘。切步驟不另開一份來源、不突然跳回開頭；切換聲音時停止舊聲音，避免兩個播放器互相干擾。

```text
歌曲名稱                         保存狀態
[① 主音與調式] [② 根音] [③ 和弦]
目前假設：G 大調 · 可修改／未定也可繼續

共同區：選段、來源時間、原曲、循環、音量

① 主音候選與十二音 → 大／小／未定 → 採用工作假設
② 低音域參考音 → 逐半音比較 → 採用根音／待聽
③ 錄音線索 → 和弦與組成音 → 比較區別音 → 採用和弦

我的行進                         連聽／備份
```

手機的步驟列可折行；同一候選的名稱、組成音、試聽與採用靠近。分析細節折收，不能用診斷表取代主要聽辨流程。音量、主音假設與當段保持可見，但不增加一堆必要設定才能開始。

## 現有程式的可用部分與缺口

1. `analyzers/chords/chordino.py` 呼叫 `estimate_key_from_chords`，原調性是和弦衍生估計；無事件還會回傳C大調。新工作區不得把這個預設當證據，也不得拿同一批和弦反推調性後宣稱是第二份獨立支持。
2. `root_candidates.py` 將217-state emission合成十二根音分數。現存精簡快取已丟失和弦性質，亦不是原始chroma或逐音偵測。第三步不能反向從這十二數字捏造G–B–D已被錄音確認。
3. 既有音樂字典、Chordino原始profile與指型工具可沿用，但必須分開字典覆蓋、聲學支持及可彈指型。配置、Capo不等於原曲和聲證據。
4. 共同播放、來源指紋、版本衝突、離線草稿及根音保存已有基礎，可沿用；已採用稿不能被新的自動分析覆寫。

聲學工作先比較兩條已界定的路徑：保留原profile資訊供「可能和弦」排序，另取得原音訊的音級線索供觀察。前者不是獨立驗證後者；兩者都要保留來源、範圍與方法。優先重用既有完整trace，不為展示候選就重跑所有歌曲。任何新增音訊處理先在獨立快取驗證，沒有支持就顯示線索不足。

## 保存與跨步驟修改

根音v1文件保留相容性。新調性／和弦工作稿採獨立、具來源指紋與版本的文件；不讓舊client默刪新增欄位。組成音觀察另記來源為人工／聲學／理論，人工採用不變成訓練真值。

和弦判斷須綁定區段id、起訖與所據根音。分段、合併或改根音後，受影響的和弦標為需重確認，保留舊判斷供復原，不靜默刪除。改主音／調式只更新解釋與候選排序，不改原音、不移調、不清掉使用者已選的和弦。跨分頁仍採版本衝突保護；三步共同備份必須包含所有工作判斷及來源。

## 反思與驗收

- 三步是學習支架，不能成為「第一步必須答對才能繼續」的關卡。
- 調內約束曾在既有九來源實驗失敗；本版不重啟硬排除調外音，不將候選品質失敗改稱通過。
- 「合得上的音未必是根音」需落到區別音與前後文比較；只增加頁籤不會解決這個問題。
- 組成音拼寫必須照和弦度數保留正確字母，不能把全部升降音機械改成固定平音名稱；C#大三和弦的三音須正確處理。
- 控制案例至少涵蓋關係大小調、A小調中的E7、C/E轉位、相同音集合但不同根音、沒有三音、和弦外旋律、未知／無和聲與錯分段。
- 聲學排序沿原九來源逐曲報告，固定參考與時間；新增參考須獨立標註，使用者採用與另一模型輸出都不當真值。若重新設新實驗門檻，必須在執行前固定，不能改原失敗紀錄。
- 工程檢查涵蓋修改調性不移調、根音修改使和弦需重確認、舊稿兼容、備份還原、離線／雙分頁、三種試聽及換步驟無殘音、手機與鍵盤。

## 後續實作順序

先固定三步資料契約、音樂字典與以上反例，再接共同工作區及第一步人工調性假設；第二步沿用現有根音能力。第三步先完成可核對的候選組成音與試聽，再接通有來源的音訊線索與候選排序，保留未知狀態。最後整合保存、失效提示與完整行進，全部自驗後才交下一次完整試用。

本次沒有將此文件列為新功能已上線，也沒有擴張到全自動主旋律、完整吉他聲部還原或模型訓練。
