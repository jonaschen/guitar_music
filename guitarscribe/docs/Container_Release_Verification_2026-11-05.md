# Codex：容器發布驗證報告（2026-11-05）

已完成 Linux x86_64 的獨立容器啟動、手機／桌面操作、真實分析、重啟及備份還原。這一段完成三項部署修正；**不代表任選歌曲的音樂品質已達標，也不是常駐雲端上線已完成**。目前受邀站保持原有執行環境與資料。

## 修正與證據

1. **部署缺少已接受的拍格恢復。** 舊映像沒有 madmom，Compose 也未開啟恢復。補入固定來源版本的 DBN 解碼依賴、保留授權文件，並啟用與現行試用站相同的受保護恢復。沒有加入新模型／權重，也沒有重新啟用已被否決的主速度連續性規則。
2. **明確限制安裝範圍。** 重整建置、把套件安裝移到程式複製後時出現 `Multiple top-level packages ... ['app', 'output', 'fixtures']`。明確指定 Python 套件範圍，映像只複製程式、腳本與範例；排除 output／環境設定。本機分析資料不再進入映像，程式修改也不必重裝全部依賴。
3. **後端重建後網站 502。** 強制將後端位址從 `.2` 換成 `.4`，健康檢查通過後代理仍回 502。改用 Docker DNS 與 Nginx 動態 upstream 解析；再次強制換址，前端容器 ID 保持不變，API 恢復 200。採用方式依 [Nginx 官方 resolve／zone 文件](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#server)，實測 Nginx 1.30.6。
