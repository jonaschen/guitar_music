# 根音抓歌協作第一版計畫與設計

2026-11-12。使用者將方向改為互補式抓歌練習：軟體提供最多三個根音線索、可比較的聲音與方便修正的工作頁，使用者決定要採用的音。先完整規劃、反思與檢驗，再完成此版功能及 UI，最後才邀請使用者試用。主旋律自動辨識繼續凍結。

## 產品承諾與範圍

協助使用者完成一段自己喜歡的歌曲，逐段聽原曲、比較候選根音、保存自己的行進。根音指和聲根音音級，C/E 的根音為 C；不是最低音、貝斯譜或完整和弦。採用 C 也不代表已確認 C 大三和弦。輸出以實際發聲音高為準，不疊加 Capo。

主要體驗是協作。可選「先自己聽」隱藏線索，但不設分數、正誤評語或強迫作答。使用者採用代表個人判斷，不是真值、不自動訓練模型。沒有證據時顯示線索不足，仍能循環、選十二音、保留待聽。

第一版是一個完整的根音練習工作區，接在既有歌曲頁。既有分析入口、和弦稿、歌詞簡譜筆記與修訂保留。這次不把未完成的練習頁取代首頁，也不擴張到多人即時協作、課程商店、模型訓練或自動完整和弦編配。

## 一次完整操作

1. 從已分析歌曲開啟「根音抓歌練習」，載入原曲與獨立練習進度。首次按「準備候選」取得聲學線索；等待時仍可手動聽辨。
2. 從行進列選一段，預設循環該段及少量前後文。未確認拍格使用秒數，不捏造小節。沒有分析事件的空白也保留為可選區段。
3. 按「聽原曲」，可切原曲加根音或只聽根音。三個同等視覺權重的音名按鈕只試聽、不保存；候選依固定排序顯示，不顯示假百分比。
4. 選「採用這個根音」才確認。可選「其他音」、或「還聽不出來」保存待聽。採用後留在當段，按「下一段」再前進，不突然換題或捲動。
5. 若不是換音位置：暫停，在游標處分段；可將當段與下一段合併，再重聽。結構改動後相關確認重設為待聽，不把兩個判斷偷偷合成一個。支援復原／重做。
6. 可整段連聽自己的行進，未決區段不補造音。重開同曲能續做，下載帶時間與判斷狀態的 JSON／文字；完整備份可還原到同一來源。

## 畫面與互動規格

第一視覺焦點是正在比較的音，不是診斷表。使用現有字體與歌曲頁色系，不增加圖庫依賴。設計 token：白色 #ffffff、紙面灰 #f4f6f8、深墨 #203345、次文字 #526477、選中藍 #185a9d、待聽褐 #785016。正文 16px，音名 32px，歌名 24px，輔助 14px；8px 間距。狀態同時以文字／符號呈現。

```text
歌曲名稱                              返回和弦頁
根音抓歌練習              已確認 3 段 · 待聽 8 段

行進    C ✓   A ✓   ? ◀   F ?   —     （可橫向選段）

正在聽 0:18.4–0:21.0              上一段  下一段
原曲 ──────────●─────────────────
播放／暫停  循環這段  原曲／原曲＋根音／根音

試試這幾個音       [ C ]   [ E ]   [ G ]
                   目前試聽 E，尚未採用
其他音 ▾           [採用這個根音]  還聽不出來

原曲音量 ────      根音音量 ────
段落調整 ▾    進度與備份 ▾     先自己聽 □
已保存                 復原  重做   連聽我的行進
```

音名是示意資料，不能把 C/E/G 當每段固定候選。手機上候選三音與採用按鈕同屏，工具折收，至少44px點擊區，320px無整頁水平溢出。切候選使用同一區段、音域、音色、音量與播放速度；重新從同一比較起點播放。原曲維持原調原速。聽辨用固定間隔單音明示為比較節奏，不冒充原曲拍點。播放狀態依實際音訊時鐘，快速切換／暫停取消舊聲音。

## 候選證據與實作方法

現況：正式 Chordino adapter 只提供最終事件。另一 chromagram 路線的 label_candidates 不能當作正式 Chordino 已有前三名。A12 已保存九份完整 Chordino trace，含217個profile（含N）、實際時間、emission及HMM path；這是可重用的研究資料，不是已上線的候選服務。

第一個固定方法：每 frame 依根音音級將profile分成12組，組內取最大 emission，再按實際時間交集加權到工作段。用最大值避免同根音的字典profile數量直接累加成優勢。取最多三個不同音級；同音異名不佔兩格。N獨立保留，不當第十三個音，也不把缺資料說成休止。完全同分、無覆蓋或全零不得硬湊高可信前三名。分數只是內部相對排序，不是根音正確機率。原HMM答案另作基準，不強制塞進前三名。

先在既有九份trace與固定參考評估；不改參考時間、不挑歌、不訓練、不上傳、不新增外部費用。用產品同一切段與聚合程式，報時間加權Top1／Top3、原版根音分數、原版錯誤被候選救回比例、覆蓋／未知、每首結果與切段混合根音問題。前三名不是三個和弦名稱去掉後綴。

開發篩選規則：三份HU33每份Top3至少80%，且原版錯誤區間至少40%含正確根音；所有來源如實列出，已知Funk2不得隱藏。這只是值得做試用介面的門檻，不是準確率承諾。若未通過，保留結果，先檢查單一失敗機制，不能事後降低門檻或只選好片段。人工流程可繼續，但不能把失敗排名偽裝成有效助手。

通過後提供本機、可取消／可重試、互斥執行的候選準備：用同版隔離觀測插件，正常分析引擎不替換；持久化精簡12音frame證據，附音訊／引擎／聚合版本身分。分段／合併時只重新聚合快取，不重跑整曲。未安裝觀測插件明示不可用，不悄悄換模型或捏造候選。新增部署路徑須能重建，不能只靠個人/tmp檔。

## 工作資料與保護

每個來源獨立練習文件：schema、來源job／音訊範圍指紋、版本、區段id／起訖、採用音級或null、待聽／已確認、更新時間。候選證據、試聽中的音、已採用的音分開；只試聽不寫入。候選刷新不覆蓋人選。練習不改原Score、歌詞筆記、和弦修訂或調性估計。

獨立SQLite保存，版本比較阻止雙分頁覆蓋。保存失敗保留本頁草稿與下載入口；提供明確重新載入，不自動蓋掉衝突資料。重開可恢復本分頁草稿。切來源取消舊請求，資料指紋不符不得套入。備份匯入驗證同來源、區段時間、音級與schema，還原可復原。音訊過期仍能讀保存進度及下載；無聲音時明示不能原曲比較。

## 計畫反思與修正

| 可能失敗 | 對計畫的修正與檢查 |
| --- | --- |
| 把工作轉嫁給使用者 | 以完成一段歌曲的操作／時間及能否獨立完成為成效，不以確認數量當成功；保留不確定，不逼整首作答。 |
| 前三候選沒有正解 | 先做Top3門檻；永遠可選十二音與待聽；不提供自動對錯評分。 |
| 候選引導使用者猜第一個 | 三音同權重、不預選採用；可先隱藏提示；沒有「最正確」文案。 |
| 分段錯導致沒有單一答案 | 納入分段／合併／前後文循環；混合根音區段保留量化失敗，不用多候選掩蓋。 |
| 原曲低音不是和聲根音 | 用聲學和聲profile排序，不把低音當真值；說明這是根音探索。 |
| 平均高分掩蓋失敗曲 | 逐來源數值、未知涵蓋、原錯誤救回均列出；不外推華語流行全域。 |
| UI累積成另一個複雜編輯器 | 全頁一個聽辨工作區，前三音與採用為核心；進階折收，不加診斷儀表板。 |
| 軟體宣稱學會使用者偏好 | 只保存個人工作稿；沒有訓練、跨曲推廣或自動擴散修改。 |
| 工程通過冒充使用者接受 | 完整功能與UI先自驗，最後才交一次整體試用，保留主觀結果未知。 |

## 實作順序與完成條件

1. 計畫與反思落地；候選聚合、固定九來源報告與反例測試。
2. 候選快取／準備服務、根音文件保存與來源身分／衝突保護。
3. 完整工作區：循環與三聲音模式、最多三候選／十二音、先自己聽、採用／待聽、上一段／下一段、整曲行進、分段／合併、復原／重做、進度恢復、下載／匯入。
4. 工程驗收：真音訊候選整合、原稿不變、瀏覽器實際聲音排程、快速切換取消、跨來源請求、雙分頁／離線恢復、重開、空結果、手機與桌面及鍵盤。跑相關回歸與build。
5. 發布完整候選入口（沿既有受邀本機試用範圍），保留回退與資料備份；此版全項完成才邀使用者做一次「完成一段自己喜歡的歌」試用。使用者不需先做工程測試或逐輪盲聽研究。

本文件是第一版交付範圍；後續改動須記錄理由與缺口，不可把未完成項目悄悄移到第二版。學習成效、長期音感進步及任選新歌品質須後續證據，這次不承諾。

## 第一輪檢驗後的單一修正

max-profile方法未過篩選：HU33 Top3為84.4%／68.6%／79.7%，錯誤救回56.4%／24.6%／24.3%。不能升為有效候選助手。核對實際217-state字典後發現每個根音恰有18個profile，根音間數量沒有不平衡；原先取max的理由過度保守，也丟失同根音其他種類的共同支持。

下一個固定假說：同根音18項emission取平均，再按相同區段時間加權，可比只保留最高項更適合根音線索。每個根音同等數量，因此亦與同組總和具有相同排序；N仍以單項值獨立比較。仍非校準後驗機率。九來源、原參考、時間、Top3與錯誤救回門檻保持不變，新增推論0。只做此一比較，不掃描混合權重／平滑參數。max結果保留；若仍未過，停止宣稱三候選可靠，依使用者已明確的互補定位另記產品決策，不事後修改此實驗門檻。

第二輪同樣未過：HU33 Top3為79.8%／69.8%／88.7%，救回43.6%／35.2%／58.0%；Funk2僅52.4%。兩個方法均記為失敗，停止此輪排名優化。原定「通過才做候選UI」會讓工程又回到無限等待辨識改善，與使用者明確要求承認極限、完成互補式工具衝突，因此修正產品交付決策：完成獨立、明示實驗性的練習工作區，固定mean方法提供「三個參考音」，清楚提示三音都可能不合，支援十二音與不確定；不稱可靠前三名、不自動採用、不替換原站預設。這是放寬試用範圍的產品決策，不是實驗通過或降低原門檻。正式音樂品質及易用性仍待驗證。
