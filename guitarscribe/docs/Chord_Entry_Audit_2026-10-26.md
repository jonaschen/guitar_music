# Codex：唯讀的換和弦入口檢查

日期：2026-10-26。工程功能完成；Bar 7 局部候選仍待人耳判斷。「請繼續」不是接受該候選的聽感回覆。

## 目的與規則

將已定位的「辨識邊界微晚，卻錯過整個刷奏入口」變成可重現的檢查，減少每次依賴使用者定位。沿用既有條件，不做參數搜尋：

- 相鄰不同和弦沒有間隙，兩側至少當地一拍。
- 邊界位於第一拍之後，最多 50ms 且最多當地 1/8 拍。
- 目前實際演奏在那個第一拍仍刷前和弦。
- 新和弦第一刷距保存邊界至少半拍。

只報告排程事實，不判定辨識和弦、拍格相位或刻意微時差是否正確。人工修改仍可被報告，但明確標記、絕不覆寫。未找到此類問題也不代表全曲正確。

## 實作

`app/services/chord_entry_audit.py` 與 `POST /scores/chord-entry-audit`，請求 `{score, mode}`，mode 為 original／continuous／sparse。依指定演奏方案的 manifest 檢查，而不是永遠檢查原版。回傳小節、原和弦／新和弦、邊界、第一拍、首次發聲時間、各種等待量，以及明確的 score-local／原檔時間。

這是來源中立的唯讀檢查，不受 stem 限制；既有寫入式 timing candidate API 的 stem 限制保持。沒有套用、保存、全域吸附或新自動修正政策。

工作區「伴奏演奏」內新增收合的「換和弦入口檢查」：按「檢查目前演奏」顯示可能等待的位置，可定位前一個實際拍點。定位依保存拍格，不用固定 BPM 倒推；Bar 7 前一拍是 10.60 秒，而非用下一拍間隔倒推的 10.62 秒。

換模式、改譜或元件離開時取消舊請求並清除結果，不把舊方案的問題顯示在新方案上。功能沒有修改任何工作譜欄位。
