# 根音分段依附拍格：計畫、反思與驗證

使用者要求預設每小節一個根音，僅在軟體判斷小節內換和聲時例外細分成半小節／四分之一小節，所有內部邊界貼齊拍子／小節。

## 實作前決策

1. 把手動拍格寫入共用根音稿v2，分段必須符合該拍格。新練習預設115 BPM、4拍、0秒對齊，整小節一段。既有v1稿維持可讀，用具體重排預覽轉換；調整BPM或對齊點後須套用重排才變更已採用稿。
2. 自動例外使用既有來源匹配的Chordino根音觀測快取，不重跑模型，不以舊和弦碎片直接切段。每個比較窗須覆蓋>=80%、前兩名分數比>=1.5、第一名在至少70%窗長的frame中明確領先且非N佔優。先查兩半是否出現不同且穩定的根音；各半內若兩拍的可靠根音不同，再只將該半拆成四分之一。預設保留整小節；不以缺資料或歧義當成換和弦證據。固定閾值，不以兩首真曲的輸出反向調參。這是未校準的分段建議，不是和弦辨識正確率承諾。
3. 半／四分之一須分別包含整數拍；4拍小節為2／1拍。其他拍數只提供能對齊整拍的細分。檔頭／檔尾不足小節按來源裁切，清楚標示；內部邊界不得自由秒數切割，不能跨小節合併。
4. 人工覆核可把目前小節切為整／半／四分之一。自動偵測不會自行改動正在編輯的稿；預覽清楚列段數、例外及判斷移轉結果，按套用才保存。整小節相同根音直接延用；原採用根音只有完整覆蓋且一致時延用，混合／部分覆蓋改待確認，不能把已選音延長進未知處。
5. 每次真正保存時後端原子封存前一版本，提供讀取版本與恢復（經既有CAS保存）的UI；v2內可復原／重做；從v1第一次轉換不把不對拍的v1塞回復原堆疊，原稿可由封存下載，恢復預覽時先轉為目前拍格。舊client不能用v1寫掉已有v2稿，還原v1須先按目前拍格轉換。測試與發布檢查不可修改正式使用者稿。
6. UI以小節號與拍數範圍標明每段，上一段／下一段、線索查詢、試聽與採用皆依同一組段。格線點選仍可設定A/B，段落工具改為按拍細分；連聽仍在待聽段只播原曲。

## 風險與檢驗

原根音候選方法沒有通過九來源品質門檻，這次不能把量化或合成測試提升成識別改善。自動例外只作可覆核建議；保留沒有快取時一小節一段的功能。調格線不自動搬移已確認根音，而是顯示重排預覽與原判斷，避免假裝改時間仍是同一音樂判斷。

驗證：完整／半／四分之一組合、錯誤／缺漏／歧義證據、單拍瞬間雜訊、任意對齊點與裁切偏移、所有內部邊界落在拍格、不同拍數、6千段上限；新舊文件、CAS、舊client、原子封存與恢復；真WebAudio、逐段採用、重開、調拍格後重排、候選查詢新界線、四尺寸。以兩首已有快取真曲產出唯讀分段摘要（非正確率），發布前備份並確認無分析工作，發布後唯讀檢查原譜與人工稿不變。


## 實作與驗證結果

根音稿v2包含共用grid，前後端都驗證內部區間必須是該小節的整／半／四分之一且含整數拍。新稿使用一小節一段及可覆核的快取例外；舊稿保留，透過具體預覽轉換。原API的來源指紋、版本CAS、離線草稿沿用，舊v1 client不能覆寫已轉v2的稿。grid調整先視為草稿，尚未套用時停止新的根音採用，以免把兩套時間混用。已保存原版本原子寫入root_practice_history；UI列最近50個版本供下載或預覽恢復，資料庫保留所有封存。

自動細分依根音變化，不宣稱能辨認同根音的和弦性質變化。整／半／四分之一可混合（例如前半兩個單拍、後半兩拍），每段仍是合法單位。缺觀測、N佔優、第一名不明確或瞬間跳動皆不據以細分。所有判斷仍需人耳覆核，未把已失敗的根音候選品質門檻改成通過。

33項後端測試通過，24項完整前端案例通過，手機標題及同小節拍號呈現修正後5項相關案例重查通過，TypeScript/build通過。新增API測試最初因測試fixture匯入路徑錯誤未執行，改為自足fixture後通過。新增互動測試揭露結構復原後選段跳到第一個待聽小節；已修正為沿目前時間保留所在段，完整流程重查通過。

兩真曲沿用匹配來源的觀測快取，沒有模型重跑或參數追分。固定115 BPM、4拍、15.959秒為工程檢查格線：膽小鬼125小節／147段、19小節細分、3段延用根音／9段待確認；沒那麼簡單147小節／168段、12小節細分。第二首BPM只是時間格測試條件，不是歌曲速度判定。每首約0.07秒產生計畫；音樂正確性無參考標註，標為未知。

正式檢查呼叫唯讀預覽API，再只在隔離瀏覽器攔截GET載入提案，查看套用後的UI與真音訊，未向正式服務PUT。四尺寸無橫向溢出或頁面例外；Score與原根音稿相同。118舊網站檔案、4份舊資料庫及服務設定保持，根音資料庫只新增空的封存表，既有根音資料列不變。發布前無進行中分析，備份5份SQLite並通過integrity_check，再重啟同一受邀服務。
