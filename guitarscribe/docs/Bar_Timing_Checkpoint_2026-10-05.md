# 小節分界校正 checkpoint

## 方向

暫停無足夠改善證據的旋律辨識參數實驗（#2 保持開啟）。目前先做 #3／#4：讓既有分析成為可修正、可保存的草稿。此 checkpoint 不代表八小節完整修譜流程或旋律辨識已完成。

## 功能與保護

- Melody editor 所選 2–8 完整小節可展開「所選小節分界校正（不移動音符）」。
- 首尾固定，調整內部分界；預設線性保留每小節原有拍距比例。各拍等分須明確勾選。
- 預覽改動數量後才套用，共用 score.beats；旋律、和弦、歌詞的秒數與內容不改動。
- 缺拍、裁切邊界、沒有下一小節起點的末小節、時間交錯或拍距小於 20ms 拒絕套用。
- 原曲／定位按鈕對照目前已套用的分界，不是輸入中的草稿。
- 沿用 Undo／Redo 與 Save new revision／Load melody revision，保存 provenance 校正紀錄；不覆蓋原分析。

## 使用者測試

1. 重新整理網頁；此輪僅前端修改，開發環境不需重啟後台。正式靜態部署需重新建置前端。
2. 載入歌曲／自己的修訂，展開 Melody editor，選起始 Bar 28、8 小節，再展開分界校正。
3. 先用原曲對照 Bar 30／31。可手填分界秒數，或暫停原曲後用「以暫停位置設定」。請勿猜測整段強制等分；不確定時先保留原值。
4. 測試操作可暫改一個內部分界 0.1 秒，觀察預覽、套用、Undo、Redo。這只是確認操作，不宣稱這個數值音樂上正確。
5. Save new revision 記下 ID，再 Undo、Load melody revision，確認分界恢復保存值。真正校正完成後才保留新版本。

回報：分界是否容易定位？Undo／保存重載是否符合預期？是否需要更直觀的原曲節拍對照？不要求此輪判斷旋律準確度。

## 工程驗證

TypeScript 檢查通過；Playwright 小節校正與既有旋律編輯共 24 項通過，涵蓋非法分界、非等分拍距、資料不變性、Undo／Redo 與修訂重載。瀏覽器修訂 API 使用 mock；另以現行程式執行後端 API／MIDI 44 項測試通過，不等同真實歌曲聽感驗收。

追加整合驗證：後端 API／MIDI 現為 45 項通過。使用暫存 SQLite 與真實 ASGI API，將 0／2／4 秒小節分界改成 0／2.4／4 秒，另存重載後確認 beats／provenance 保留、父版本與旋律／和弦不變。播放 manifest 的伴奏與節拍器採用新拍點；獨立解碼 MIDI 事件確認每拍伴奏起音及旋律 2.1–2.7 秒音長（容許 1.1ms tick 誤差）。這是合成案例的端到端後端驗證，未觸碰使用者資料，未代表實曲音樂驗收或 MusicXML 檢查完成。

## 後續

自動拍點修正、和弦變換時間的整段編輯、編輯區整合合奏循環、候選接受流程與跨曲品質驗收仍需推進。此工具只能修正格線，不能讓辨識錯誤的音符變正確。
